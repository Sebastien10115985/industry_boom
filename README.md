# 万得三级行业动态观察库

这是一个本地运行的 Streamlit 小程序。它内置固定的申万三级行业清单（无需万得授权，行业名称支持语义模糊匹配），可从巨潮资讯检索正式定期报告，严格按公告日构建点时快照，在每个三级行业内部计算排名，并选取前 20 名进入观察库。已购买万得时可选改用官方行业编码。

## 运行

在 Windows 自带的 PowerShell 中打开本项目根目录（即含 `app.py` 的目录），按顺序执行：

### 1. 准备 Python

本机需预先安装 Python，本项目基于 Python 3.11.6 开发，可用 `python -V` 确认版本。

### 2. 创建虚拟环境

只需运行一次，用于隔离本项目的依赖，避免与其它项目的库版本冲突。

```powershell
python -m venv .venv
```

### 3. 激活虚拟环境

```powershell
.venv\Scripts\Activate.ps1
```

如果提示「禁止运行脚本」，先放行当前用户，再重新激活：

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### 4. 安装依赖并启动

激活成功后命令行提示符前会出现 `(.venv)`，此时安装全部依赖并启动页面：

```powershell
python -m pip install -r requirements.txt
streamlit run app.py
```

仓库不包含 `data/` 目录，首次启动时本地还没有财报缓存，页面会提示无数据。
先在「行业详情」页签选定一个三级行业点「拉取近一年财报」，或按下文「在线公告命令」
一节的 `industry sync` 命令在命令行拉取，之后即可正常查看。

页面默认使用本地缓存的巨潮资讯正式定期报告数据（不含任何演示数据）。也可上传 `.csv`、`.xlsx` 或 `.xlsm`；可在页面下载空白数据模板。

也可按季度自动运行：

```powershell
python cli.py --input wind_data.xlsx --as-of 2026-10-31 --report-period 2026-09-30 --output output/2026Q3.xlsx
```

## 内置三级行业（无需万得授权）

默认模式不需要万得终端，也不需要 Wind Client API。程序内置了一份固定的申万三级行业清单（申万 2021 版）：

- 代码模块：`public_industry_taxonomy.py`（页面与命令行直接取用）
- 可审阅副本：`catalog/sw_l3_taxonomy.csv`
- 层级：31 个一级行业 → 二级行业 → 三级行业，并带成分公司数量

三级行业名称支持语义级模糊匹配，不要求与官方名称完全一致：

- `industry_match.py` 会先做精确匹配，再做包含匹配，最后用相似度排序；
- 归一化时会忽略罗马数字、`申万`、`行业`、`三级` 等无区分度的词；
- 上传数据时只要提供行业名称即可，程序自动补齐三级行业 ID 与排名模型；
- 匹配结果保留 `industry_match_score` 与 `industry_match_method`，便于人工复核。

需要刷新内置清单时执行：

```powershell
python tools/refresh_public_taxonomy.py
```

它会重新抓取公开行业总览页，覆盖 `public_industry_taxonomy.py` 与 `catalog/sw_l3_taxonomy.csv`，并写入新的快照日期。

## 可选：固化万得官方三级行业

万得行业代码和成分股属于许可数据，项目不会预置来源不明的行业 ID。如果已购买万得并希望改用万得编码，可在有 Wind Client API 权限的终端上固化一次官方快照。先在万得终端代码生成器 `CG` 中确认当前许可对应的三级行业 ID 和名称字段，再执行：

```powershell
python online_cli.py catalog-wind `
  --effective-date 2026-10-31 `
  --industry-id-field <三级行业ID字段> `
  --industry-name-field <三级行业名称字段>
```

若没有 WindPy 权限，但有一份成分股表（万得、东方财富、同花顺等任意公开来源均可），只要包含行业名称、证券代码、简称和市值即可固化：

```powershell
python online_cli.py catalog-freeze `
  --input wind_official_constituents.xlsx `
  --effective-date 2026-10-31 `
  --seed-count 5
```

程序会生成并固定 `catalog/wind_l3_catalog.csv` 和 `catalog/wind_l3_constituents.csv`，同时在 `catalog/catalog_metadata.json` 保存来源、日期和 SHA-256 校验值。“知名公司”不采用网络文章的主观名单，而定义为每个三级行业在快照日市值前 N 名，保证可重复、可更新；完整成分股仍全部保留。若表中只有行业名称没有行业 ID，程序会用上一节的模糊匹配自动补齐三级行业 ID。

## 在线公告命令

公告元数据和 PDF 来自巨潮资讯正式披露网站。先同步种子公司验证数据质量，再同步全部公司：

```powershell
python online_cli.py update --scope seed --as-of 2026-10-31
python online_cli.py update --scope all --as-of 2026-10-31
python online_cli.py update --company 600000.SH --as-of 2026-10-31
```

然后按最新已披露的共同报告期排名：

```powershell
python online_cli.py rank `
  --as-of 2026-10-31 `
  --output output/latest.xlsx
```

网页侧栏也支持中文命令：`更新知名公司`、`更新全部公司`、`更新公司 600000.SH`，可追加 `截止 2026-10-31`。排名坚持使用同一报告期，避免把某公司的年报与另一公司的三季报直接比较。

巨潮网页查询接口可能调整；程序采用低频串行访问。PDF 自动提取结果保留 `source_url`、`extraction_confidence` 和 `needs_review`，低置信度记录必须打开原公告人工复核。若已购买万得结构化财务数据权限，生产环境应优先直接取结构化字段，PDF 提取仅作为可追溯后备。

## 通用行业算法

所有指标均在同一个万得三级行业内转换为 0—100 的百分位分：

| 指标 | 权重 | 方向 |
|---|---:|---|
| 营收增长率 | 12.5% | 越高越好 |
| 利润增长率 | 12.5% | 越高越好 |
| 毛利率 | 25% | 越高越好 |
| 市值 | 10% | 越高越好 |
| 营收 | 20% | 越高越好 |
| 净利润 | 20% | 越高越好 |

增长合计 25%。利润上年同期为正时使用普通同比；上年同期不为正时使用对称增长率：

\[
g=\frac{2(P_t-P_{t-1})}{|P_t|+|P_{t-1}|}
\]

它能合理区分“亏损转盈利”和“盈利转亏损”，避免普通同比在负基数时失真。

原始综合分为 `Σ(权重 × 百分位分)`。缺失指标暂按 50 分中性值处理，再使用以下完整度惩罚：

\[
S=S_{raw}\times(0.8+0.2C)
\]

其中 \(C\) 为已有数据对应的权重之和。默认 \(C<60\%\) 的公司不参与排名。

## 行业景气度（国家统计局口径）

每月国家统计局公布规模以上工业增加值和工业企业利润后，触发一次更新，程序会滚动最近 6 个月的分行业官方数据，给出最景气的若干统计行业，并列出它们对应的申万三级行业与排名靠前的公司。

数据来源（官方公开发布，无需授权）：

- 《规模以上工业生产主要数据》附件：分行业工业增加值**当月**同比增长速度（公布约每月中旬）
- 《全国规模以上工业企业利润》附件“表3 …（分行业）”：分行业利润总额**年初至当月累计**同比增长速度（公布约每月月末）

景气度权重（0—100 分）：

| 分项 | 权重 |
|---|---:|
| 近 N 月利润增长率均值 | 45% |
| 近 N 月工业增加值增长率均值 | 25% |
| 最新月利润增长率 | 15% |
| 利润增长动量（最新 − 均值） | 15% |

缺少的分项按 50 分中性值计入，并在 `data_note` 中说明；只保留能对应到申万三级行业的统计行业，避免“金属制品、机械和设备修理业”这类没有对应标的的小类占位。

命令行：

```powershell
python online_cli.py prosperity --months 6 --window 6 --top-n 5 --output output/prosperity.xlsx
python online_cli.py prosperity --offline --window 6          # 只用本地历史，不联网
python online_cli.py prosperity --input my_nbs.csv            # 导入手工整理的分行业月度数据
```

页面：「行业景气度」页签只出**打分表**（最景气 TOP5 + 固定跟踪的行业大类），点“从国家统计局更新月度景气数据”即可；侧栏中文命令 `更新行业景气度` 同样可用。
每个统计行业大类对应的申万三级行业、全部成分公司与排名靠前公司，按大类归入「行业详情」对应子 tab 的「对应统计局大类」区块（按该大类映射的三级行业多数落在哪个 tab 归位）。

统计行业与申万行业的对应写在 `prosperity_mapping.py`，优先按**申万二级行业**映射并自动展开为二级行业下的全部三级行业。例如：

- 计算机、通信和其他电子设备制造业 → 半导体、元件、光学光电子、消费电子、通信设备、计算机设备等 22 个三级行业
- 铁路、船舶、航空航天和其他运输设备制造业 → 轨交设备、航海装备、航空装备、航天装备、地面兵装 5 个三级行业

`python -c "from prosperity_mapping import mapping_report; print(mapping_report())"` 可查看每个统计行业落地到多少个三级行业。

历史数据存放在 `data/prosperity/nbs_monthly.csv`（本地数据，不入库）。注意工业增加值只公布主要行业（约 20 个），其余行业该项为空并按中性值处理。

## 流动性指数

「流动性分析」页签把六个流动性指标合成一个指数：先**同向化**（宽松 = 数值变大；利率类乘 −1），
再按滚动窗口做 **Z-score 标准化**（周度指标 52 周、月度指标 36 个月，避免全样本标准化的前视偏差），
最后加权合成。月度数据按次月 10 日生效，近似央行公布时点，避免使用未公布数据。

| 分组 | 指标 | 频率 | 方向 | 在总指数中权重 | 在子指数中权重 |
|---|---|---|---|---:|---:|
| 短端资金价格指数（周度更新） | DR007（存款类机构7天回购定盘利率 FDR007） | 周频 | 越高越紧 | 15% | 37% |
| 短端资金价格指数（周度更新） | 十年期国债收益率（中债国债收益率曲线） | 周频 | 越高越紧 | 15% | 37% |
| 短端资金价格指数（周度更新） | 两融余额（场内杠杆资金体量） | 周频 | 越高越宽松 | 11% | 27% |
| 信用货币增速指数（月频更新） | M1-M2 剪刀差（交易活性，优先级更高） | 月频 | 越高越宽松 | 18% | 31% |
| 信用货币增速指数（月频更新） | M2 同比增速 | 月频 | 越高越宽松 | 12% | 20% |
| 信用货币增速指数（月频更新） | 社融存量同比（实体信用是根基） | 月频 | 越高越宽松 | 18% | 31% |
| 信用货币增速指数（月频更新） | 两融余额同比（增速类，由两融余额水平派生） | 周频 | 越高越宽松 | 11% | 19% |

「在子指数中权重」= 该指标权重 ÷ 组内权重之和（短端 41%、信用 59%），
例如 DR007：15%÷41%≈37%。两列各自纵向求和均为 100%。
组内某指标缺失时，剩余指标按「在子指数中权重」的比例归一化补位。

分组依据：**短端只放价格与体量类指标**（利率、两融余额水平，反映资金「贵不贵」「多不多」）；
**两融余额同比是增速类**（变化率，与货币信贷增速同性质），归入信用货币增速指数。
利率类权重从各 20% 降到 15%，降出的 10% 加给两融余额与两融余额同比（各 6%→11%）：
利率长期低位徘徊、区分度有限，杠杆资金体量与增速更能反映风险偏好变化。
对应到子指数内部：利率两项合计从 87% 降到 73%，两融余额从 13% 升到 27%。

- **流动性指数 = 0.41×短端资金价格指数 + 0.59×信用货币增速指数**（组权重 = 组内指标权重之和）；
  组内某指标缺失时，该组按现有指标归一化补位并在页面提示。
- 页面顺序：流动性指数 → 短端资金价格指数 → 信用货币增速指数 → **原始指标走势** → 数据源留存。
  每个指数给出最新值、较上期变化、近一年分位与趋势判断（周度对比周、月度对比月）。
  「原始指标走势」按 DR007 → 十年期国债收益率 → 两融余额 → M1-M2 剪刀差 →
  M2 同比 → 社会融资规模存量 → 社融存量同比 → 两融余额同比的顺序画出原始值曲线
  （未同向化、未标准化），直接读取本地缓存，离线可查看；两融余额、社融存量以万亿元展示。
- 指数图上叠加两条参考：**滚动均值**（虚线）与 **80% 波动区间**（灰色带，
  取同窗口的 10%~90% 分位；周度窗口 52 周、月度窗口 12 个月）。指数超出灰带
  即进入近一年最宽松或最紧的 10% 区间，可直观判断当前读数是否「出格」。

数据源（每类留存于 `data/liquidity/{指标}.csv`，含 date、value、source_url、retrieved_at，可随时回放趋势）：

| 指标 | 来源 | 更新方式 |
|---|---|---|
| DR007 | 中国货币网·全国银行间同业拆借中心（回购定盘利率） | 自动，页签按钮 |
| 十年期国债收益率 | 中债国债收益率曲线（中央结算公司） | 自动，页签按钮 |
| 两融余额 | 沪深交易所两融余额（东方财富数据中心汇总） | 自动，页签按钮（同比由余额派生） |
| M1/M2、剪刀差 | 央行货币供应量统计（东方财富数据中心转载） | 自动，页签按钮 |
| 社会融资规模存量 | 央行「调查统计司-统计数据-社会融资规模」年度栏目 | 自动，页签按钮 |
| 社融存量同比 | 同上（直接取存量统计表的「增速」列） | 自动，页签按钮 |

社融两项的来源说明：央行官网按年归档「统计数据」，每年一个「社会融资规模」栏目页，
挂着《社会融资规模存量统计表》（htm/xlsx/pdf 三种格式）。程序先解析年度栏目地址，
再取存量表 htm，逐月读出「社会融资规模存量」行的（存量, 增速）二元组，回填最近 5 年，
覆盖 36 个月 Z 窗口。这与央行公众号每月发布的《金融统计数据报告》同源同口径。
抓取失败时可临时把数值写入 `data/liquidity/social_financing_yoy.csv` 应急。
两融余额同比不单独存盘，由 `data/liquidity/margin_balance.csv`（余额水平）在计算时按 52 周派生。

命令行更新（页面按钮等价）：

```powershell
python -c "from liquidity_sources import update_liquidity_cache; print(update_liquidity_cache())"
```

相关模块：`liquidity_sources.py`（抓取与缓存）、`liquidity.py`（同向化、标准化与合成）。

## 三级行业财报与子行业排名

以某个申万三级行业为单位，取其**全部成份公司**，到巨潮资讯逐个检索截止日之前近一年（可用 `--lookback-days` 调整）的正式定期报告，从公告原文抽取财报信息，再用现有算法在该子行业内部排名。

以「数字芯片设计」为例，其 55 家成份公司全部参与：

```powershell
python online_cli.py industry sync  --industry 数字芯片设计 --as-of 2026-11-02 --lookback-days 365
python online_cli.py industry rank  --industry 数字芯片设计 --as-of 2026-11-02 --output output/数字芯片设计.xlsx
python online_cli.py industry list                      # 已同步财报的三级行业
```

### 公告检索的两个坑（已修复）

想拿到「上年同期」数据来算增长率，检索必须完整，否则只能退回到 PDF 里的同比字段：

1. **三季报标题多写作「三季度报告」**，早期正则只认「第三季度报告」，导致三季报整批漏检。
2. **公告多的公司翻不到半年报**：全文检索按日期倒序，大型药企一年几百条临时公告，
   只看前一两页会全部错过定期报告。现在先用全文检索取到巨潮机构 ID，
   再按「机构 ID + 定期报告类别」精确查询，一页就能取全近两年定期报告。

## 子行业模型

固化目录时会为每个三级行业保存 `model_type`。默认规则可在 `industry_catalog.py` 调整，目录中的明确配置优先于关键词推断：

| 模型 | 营收 | 净利润 | 营收增长 | 利润增长 | 毛利率 | 适用示例 |
|---|---:|---:|---:|---:|---:|---|
| `growth` | 10% | 15% | 20% | 30% | 25% | 软件、半导体、电子设备 |
| `innovative_drug` | 10% | 15% | 20% | 30%（对称增长率） | 25% | 化学制剂、生物制品、CXO |
| `quality` | 10% | 25% | 10% | 15% | 40% | 食品饮料、个人用品、品牌消费 |
| `cyclical` | 20% | 30% | 10% | 25% | 15% | 金属、矿业、化工、能源 |
| `scale` | 30% | 30% | 10% | 15% | 15% | 公用事业、运输、建筑工程 |

未匹配行业继续使用通用模型。行业模型只改变权重，所有公司仍在自己的三级行业内部转成百分位分。

### 创新药模型与对称利润增长率

创新药公司常年在盈亏之间摆动，用普通同比会出现荒谬值（上年亏 100 万元、今年赚 10 万元，算出来是 +110000%）。
`innovative_drug` 模型把利润增长指标换成**对称增长率**：

```plaintext
对称增长率 = 2 × (本期净利润 − 上年同期净利润) / (|本期净利润| + |上年同期净利润|)
```

取值范围固定在 [-2, 2]，亏损收窄与盈利增长可以放在同一尺度上比较：上年 -100 万、今年 -10 万得 +1.64，
上年 100 万、今年 120 万得 +0.18。分母为 0（两期都是 0）时留空，不参与该指标计分。

命中行业名 `制药生命科学工具`、`生物科技`、`化学制剂`、`生物制品`、`医疗研发外包` 时自动使用该模型。
普通模型仍保留「上年同期为负才改用对称式」的原规则，两者互不影响。

## 金融行业模型

金融企业不宜使用毛利率、普通营收规模作为核心横向指标，因此程序按 `model_type` 使用独立模型：

- `bank`：ROE 20%、净息差 10%、营收增长 7.5%、利润增长 12.5%、不良率 15%、拨备覆盖率 10%、核心一级资本充足率 10%、成本收入比 5%、市净率 7.5%、市值 2.5%。
- `securities`：ROE 25%、营收增长 10%、利润增长 15%、净资本比率 15%、风险覆盖率 10%、营业利润率 10%、市净率 10%、市值 5%。
- `insurance`：ROE 20%、保费增长 15%、利润增长 10%、偿付能力充足率 15%、综合成本率 15%、投资收益率 10%、市净率 10%、市值 5%。

不良率、成本收入比、市净率、综合成本率按越低越好计分。保险模型更适合财险；寿险可在 `ranking.py` 中将综合成本率替换为新业务价值增长率或剩余边际指标。

如果在线 PDF 尚未提取到足够的金融监管指标，程序会让该三级行业整体切换到 `financial_report` 后备模型：营收 20%、净利润 30%、营收增长 20%、利润增长 30%，并在 `model_fallback_reason` 中明确记录原因。补齐 Wind 结构化专业指标后才恢复银行、证券或保险完整模型，不会在同一行业内混用两个模型。

## 输入数据

必需字段：

- `company_id`：证券代码
- `report_period`：报告期
- `announcement_date`：公告日期
- `industry_l3_id` 或 `industry_l3_name` 之一；只给名称时会用内置目录模糊匹配补齐 ID

建议同时提供 `company_name`、`industry_l3_name`、`model_type` 及对应模型所需指标。程序兼容模板中列出的常用中文列名。金额单位可自定，但同一期数据必须保持一致；比率可以统一使用小数或百分数，横截面百分位排名不受统一倍数影响。

应将每次修订公告保留为独立记录；程序会在截止日之前保留同一公司、同一报告期最后一次公告。市值建议使用排名截止日收盘市值，并避免把截止日之后才获知的数据写入历史快照。

## 注意

这是研究筛选模型，不是收益预测模型。正式使用前应做历史点时回测，纳入退市公司，计入交易成本，并检查行业样本数、财务重述和极端值。
